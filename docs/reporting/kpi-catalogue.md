# Service quality KPI catalogue

Status: Step 27 reporting contract  
Owner: IT Manager  
Default reporting time zone: `America/Tortola`

## Reporting boundary

The manager dashboard and CSV export use the same reporting service and the same filtered ticket facts. Date inputs are interpreted as whole local calendar days in the selected permitted property time zone. The end date is inclusive in the interface and becomes the next local midnight internally. A report is limited to 366 days and 50,000 candidate facts so an interactive request cannot become an unbounded database scan.

Each ticket has a private reporting fact. It captures the property, department, category, assignee, asset, asset location, time zone, and SLA policy labels that applied to the ticket. A deliberate change to the ticket captures the new selection. A later rename of a category or user, an asset move, or an SLA policy edit does not rewrite an earlier fact. Existing tickets are captured once when the migration is applied. Their earlier labels are therefore the labels known at that migration boundary.

Cancelled tickets are excluded from response, resolution, SLA, and reopen measures. They remain part of intake volume and source, category, priority, property, and department demand because they consumed intake capacity. Null results are shown as “Not available”, never as zero.

## Filters and scope

The dashboard supports date, property, department, category, source, and time-zone filters. Property scope is derived server-side from the viewer’s property-specific `report.read` assignments. A submitted property outside that scope is rejected rather than ignored. Department, category, and source filtering is also applied on the server.

The selected report time zone changes calendar boundaries only. It does not replace a ticket’s SLA time zone. First response and resolution calculations always use the SLA snapshot captured with that ticket.

## Export privacy

CSV exports contain aggregated KPI and grouping rows only. They do not contain requester names, email addresses, ticket subjects, descriptions, comments, attachment names, device telemetry, provider payloads, or individual ticket identifiers. Formula-leading cells are neutralized and all quotes, delimiters, and line breaks are escaped. Responses are marked private, no-store, and `nosniff`.

## Reproduction example

Given three synthetic facts in `America/Tortola`, two created between local midnight on 2026-08-01 and the exclusive next midnight after 2026-08-31, Ticket volume is:

```text
Numerator ticket IDs: synthetic-001, synthetic-002
Denominator: not applicable
Result: 2 tickets
```

The reporting engine returns the sorted included identifiers with the volume result for test evidence. The CSV and dashboard receive the same result object, so this sample can be independently reproduced from the same records without reverse-engineering chart rendering.

## Query and retention notes

Reporting facts live in the private `service_desk` schema and are not granted to browser database roles. Composite indexes cover organization plus period, property plus period, status plus period, category plus period, open assignee workload, and asset recurrence. No view or separate analytics platform is introduced. If volume approaches the interactive 50,000-fact ceiling, the next decision is a reviewed PostgreSQL summary strategy, not a silent increase to browser request cost.
